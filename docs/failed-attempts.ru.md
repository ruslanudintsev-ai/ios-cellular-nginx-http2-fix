# Неудачные и неоднозначные проверки

Эти эксперименты помогли сузить проблему, но большинство не были чистыми воспроизводимыми контрольными тестами. Ниже приведены наблюдения именно этого расследования, а не универсальные выводы.

| Эксперимент | Наблюдение | Что он показал и чего не доказал |
|---|---|---|
| Копия сайта на втором сервере | В проверке владельца копия тоже зависала на iPhone. | Простая смена сервера не устранила симптом. Это не изолировало ПО сервера, сетевой маршрут или влияние времени. |
| Другой hostname на исходном сервере | Сначала открылся, затем позднее тоже перестал. | Один лишь другой hostname не оказался стабильным решением. |
| Минимальный HTML или отключение JavaScript | Некоторые упрощённые ответы открывались, но результаты менялись; отключение JavaScript на iPhone не решило проблему полного сайта. | Рендеринг приложения не объяснял каждый сбой. |
| Отключение gzip | В одних попытках страница открывалась, в других нет. | Повторяемая причина, связанная только с gzip, не установлена. |
| Статические HTML, CSS и изображения | Упрощённая страница иногда открывалась. | Маленькие ответы были полезным контролем, но полный сбой сайта надёжно не воспроизводили. |
| Основные JavaScript-файлы | В одном тесте успешно загрузились 11 проверенных файлов. | Однократный успешный тест ресурсов не доказывает исправность каждой загрузки страницы. |
| Отключение Next.js prefetch | Изменение выложили, но по сообщению владельца production-проблема осталась. | Это конкретное исправление на уровне приложения не помогло. |
| Другие браузеры и приватный режим | По сообщению владельца, проблема сохранялась в Safari и других браузерах, в том числе в приватном режиме. | Один только кеш браузера не объяснял симптом. |
| TLS, сертификаты и кеш сессий | Проверки сертификата и TLS 1.2/1.3 проходили; общий кеш TLS-сессий был настроен. | Явной ошибки TLS-конфигурации не нашли. Успешный handshake из командной строки не воспроизводил все сбои iPhone. |
| Захват пакетов | Захват проводился, но однозначную причину не выявил. | Сетевой захват полезен, когда связан с точным воспроизводимым тестом и анализируется на правильном уровне. |
| HTTP-запрос из командной строки | Один запрос вернул HTTP 200; другая попытка завершилась тайм-аутом при TLS. | Наблюдались разные режимы сбоя. Один HTTP 200 не доказывал отображение страницы или загрузку всех ресурсов. |

## Выводы из неудачных попыток

- Успешный HTTP-статус не равен полностью отображённой странице.
- Нельзя выводить единственную первопричину из нерегулярных проверок, если меняются сеть, кеш, hostname или устройство.
- Сбои до HTTP нужно отделять от ситуаций, когда HTML уже получен.
- Исправление одной JavaScript- или gzip-ветки нельзя называть сетевым решением без повторяемого сравнения.
- Самым полезным разделителем стала смена протокола: сначала успешная проверка canary, затем мгновенное открытие того же production-хоста после включения HTTP/2.

Результат с HTTP/2 сильнее ранних попыток, но он не раскрывает точный механизм.
