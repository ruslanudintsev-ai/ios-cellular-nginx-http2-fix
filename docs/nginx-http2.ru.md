# HTTP/2 в Nginx: настройка и откат

В этом разделе описано изменение, использованное в кейсе. Это не универсальная инструкция: сначала проверьте сборку установленного Nginx и точные виртуальные хосты.

## Версия и модуль

На проверенном сервере работал Nginx 1.30.5 со встроенным модулем HTTP/2. Согласно документации Nginx, директива `http2 on;` доступна начиная с версии 1.25.1 и допустима в контекстах `http` и `server`. См. [официальную документацию модуля](https://nginx.org/en/docs/http/ngx_http_v2_module.html).

Для HTTP/2 поверх TLS также нужна поддержка ALPN. Сохраните текущую TLS-конфигурацию и работу с сертификатами; не копируйте старые списки шифров и не снижайте минимальную версию TLS.

## Пример конфигурации

В современных версиях Nginx включайте HTTP/2 внутри нужного HTTPS server-блока:

```nginx
server {
    listen 443 ssl;
    http2 on;
    server_name example.com;

    # Сохраните существующие сертификат, TLS policy и настройки сайта.
}
```

В этом случае директива была добавлена только в HTTPS-vhost основного домена и www. Глобально её не включали, конфигурации других сайтов не меняли.

## Проверьте оба протокола

До и после изменения проверьте синтаксис и доступность обоих вариантов:

```sh
nginx -t && nginx -s reload

curl --http2 --compressed -sS -o /dev/null \
  -w 'status=%{http_code} version=%{http_version} tls_verify=%{ssl_verify_result}\n' \
  https://example.com/

curl --http1.1 --compressed -sS -o /dev/null \
  -w 'status=%{http_code} version=%{http_version} tls_verify=%{ssl_verify_result}\n' \
  https://example.com/
```

Ожидаемый результат: первая команда показывает `version=2`, а принудительная HTTP/1.1 — `version=1.1`; оба запроса проходят. Ответ HTTP 200 без `version=2` **не подтверждает**, что действительно согласован HTTP/2. Обязательно проверьте реальный клиент и сеть, на которых проявлялась проблема; проверки командной строкой не заменяют этот тест.

## Откат

Удалите только директивы `http2 on;` из изменённых server-блоков, выполните `nginx -t` и graceful reload. Перед правкой сохраните точную копию исходного vhost. Не откатывайте несвязанные общие настройки TLS.

## Результат и ограничение

После включения HTTP/2 на отдельном диагностическом vhost владелец сообщил о мгновенной загрузке на iPhone. После включения HTTP/2 на production-vhost он сообщил о мгновенной загрузке того же сайта на том же iPhone, production hostname и мобильном подключении. HTTP/1.1 fallback продолжал работать.

При включении HTTP/2 также выполнялась плавная перезагрузка конфигурации Nginx, которая могла повлиять на состояние соединений. Это сильное свидетельство связи с изменением, но одно успешное открытие не позволяет полностью отделить эффект протокола от перезагрузки и не устанавливает низкоуровневую причину. На момент записи период наблюдения был меньше суток.
